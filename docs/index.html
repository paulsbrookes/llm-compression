How few bits per weight can store an LLM, losslessly?

From Shannon's source coding theorem to real Qwen2.5-0.5B weights. Short answer: bf16 weights carry about 10.5 bits of entropy per weight, a ~34% lossless reduction, and nearly all the redundancy is in the exponent.

1. The entropy floor of a quantised Gaussian

Round x ~ N(μ, σ²) to fp16 and you get a discrete source with a computable pmf. Its entropy H ≈ 13.46 bits is the lossless floor, and it's nearly scale-invariant (floating point has relative precision). The 16 bits split as sign 1.0 + exponent 2.54 + mantissa 9.97. The redundancy is almost entirely in the exponent.

3. Real LLM weights match the theory

Qwen2.5-0.5B weights are near-Gaussian (kurtosis ≈ 3.5–4.7). Their bf16 entropy is ~10.5 bits/weight, exactly the fp16 figure minus ~3 bits, because bf16 has 7 mantissa bits instead of fp16's 10. The synthetic theory predicts the real model. Query/key projections are the heavy-tailed exception (kurtosis 14–23, outlier dimensions); RMSNorm gains are bimodal. See the dashboard.

4. So why does production go lossy?

Lossless bottoms out at the ~10.5-bit floor. Deployments run at 4–8 bits via int4/int8 quantization, below the floor, by discarding information the model tolerates losing. They also decode faster: a fixed-width quantized weight is a shift-and-mask into a matmul kernel, with random access, versus a sequential entropy decode. The mantissa (least compressible losslessly, least informative) is exactly what low-bit quantization drops first. (Details in the README.)
